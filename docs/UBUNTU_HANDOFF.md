## 2. One-time setup

### Machine requirements
- x86-64 Intel/AMD CPU (not ARM), 8 GB RAM, ~20 GB free disk, 2 USB ports.
- **Ubuntu 22.04 LTS** recommended (20.04 OK; 24.04 needs extra libs, see §8).

### Step 1 — clone
```bash
sudo apt install -y gh git
gh auth login                                   # GitHub.com → HTTPS → browser
gh repo clone TejasDapse/fpga-systolic-array
cd fpga-systolic-array
```

### Step 2 — install Quartus Prime Lite (manual, from Intel)
1. Intel FPGA download center → **Quartus Prime Lite Edition → Linux**.
2. Download the installer **and the MAX 10 device file** (`max10-*.qdz`) into one folder.
   Optional: *Questa – Intel FPGA Starter Edition* (needed later for UVM, Phase 6).
3. Install and add to PATH:
   ```bash
   chmod +x qinst-lite-linux-*.run && ./qinst-lite-linux-*.run    # or setup.sh, depending on version
   echo 'export PATH=$HOME/intelFPGA_lite/<version>/quartus/bin:$PATH' >> ~/.bashrc
   source ~/.bashrc
   quartus_sh --version
   ```

### Step 3 — everything else (one script)
```bash
./tools/setup_ubuntu.sh
```
It installs Icarus/GTKWave/Python venv, the **USB-Blaster udev rule**, adds you to
the **dialout** group (for `/dev/ttyUSB0`), and runs the simulation regression.
**Log out and back in** afterwards so the dialout group takes effect.

**Expected:** all tests pass (the ~6-min N=8 full-system sim is skipped unless `SLOW=1`).
Ubuntu 22.04 ships Icarus 11 (the Mac used 13); if a test fails to *compile*, record the
error in §6 and push.

**No sudo?** The simulators can come from conda-forge instead (this is how the current
machine is set up):
```bash
CONDA_NO_PLUGINS=true CONDA_SOLVER=classic conda create -y -n fpga -c conda-forge \
    --override-channels python=3.12 iverilog verilator     # Verilator 5.x, Icarus 13
conda activate fpga && pip install -r requirements.txt
```
The udev rule and `dialout` group (steps 2–3 of the script) still need sudo once.

## 4. Hardware tasks — Phase 1 bring-up (do these in order)

### Task 1 — verify pins (before the first compile)
- [ ] Download the **DE10-Lite CD** from Terasic; run **DE10-Lite System Builder**
      (Windows tool — runs under `wine`, or use any Windows PC once).
      Tick: CLOCK, LED, Button, Switch, 7-Segment, GPIO. Generate.

- [ ] If any differ: **edit `tools/gen_quartus.py` only** (never the generated `.qsf`),

### Task 2 — compile all four designs
- [ ] `tools/build.sh all`
- [ ] Record resources, Fmax, and slack for each in `docs/results/phase1_hw.md`.
- [ ] Any compile error or negative slack → record it in §6 and push (don't guess-fix the RTL).

### Task 3 — program and check each design on the board
| Design | Command | Expected behaviour | ✓ |
|---|---|---|---|
| 01 | `tools/build.sh 01_switch_led --program` | SW[i] lights LEDR[i]; HEX all off | [ ] |
| 02 | `tools/build.sh 02_blinky --program` | LEDR0 blinks 1 Hz; LEDR9..1 count up; hold KEY0 = reset | [ ] |
| 03 | `tools/build.sh 03_hex_counter --program` | HEX counts in hex at 10/s; KEY1 pause/resume (LEDR0 = running); KEY0 reset | [ ] |
| 04 | `tools/build.sh 04_uart_echo --program` | see Task 4 | [ ] |

### Task 4 — UART echo test
Wire the **3.3 V** USB-UART adapter (jumper on 3.3 V, leave VCC unconnected):
```
 DE10-Lite GPIO header (JP1)              USB-UART adapter
   pin 1  GPIO[0]  UART_TXD  ───────────▶  RXD
   pin 2  GPIO[1]  UART_RXD  ◀───────────  TXD
   pin 12 GND                ────────────  GND
```
- [ ] `ls /dev/ttyUSB*` shows the adapter.
- [ ] `screen /dev/ttyUSB0 115200` → typed characters echo back (quit: Ctrl-A, K).
- [ ] `python host/uart_echo_test.py --count 10000` → **`0 errors, PASS`**.
- [ ] HEX5..HEX2 show the byte count, HEX1:HEX0 the last byte, LEDR9 blinks, LEDR0/1 off.

### Task 5 — commit results

```bash
git add docs/results/phase1_hw.md tools/gen_quartus.py foundations/*/quartus/*.qsf
git commit -m "Phase 1 hardware bring-up results"
git push
```
Photos/videos of the board working → `docs/results/` (keep each < 5 MB).

### Task 6 — Phase 4: accelerator bring-up (after Tasks 1–5 pass)

The accelerator's Quartus project is `quartus/` (N = 4 for bring-up). Same wiring as Task 4.
```bash
tools/build.sh quartus                       # compile: check slack >= 0, ~N² 9-bit multipliers
tools/build.sh quartus --program             # program the board
python host/host.py --tests 100              # N=4: expect PASS
```
On the board: LEDR9 blinks; after a run HEX shows PERF_COMPUTE (K + 2N − 1, hex) and LEDR8 is on.
Record resources / Fmax / slack in `docs/results/`.

**Scale to N = 8:** in `tools/gen_quartus.py` change `{"N": 4, ...}` to `{"N": 8, ...}` for
the `"."` project → `python3 tools/gen_quartus.py` → rebuild + program →
`python host/host.py --tests 1000` → `python host/host.py --bench` (CSV + plots in `docs/results/`).

| LED | Meaning |
|---|---|
| LEDR[2:0] | controller state (0 idle, 1 clear, 2 compute, 3 drain, 4 done) |
| LEDR3 | busy |
| LEDR5 | UART framing error seen → baud mismatch / noisy wiring |
| LEDR6 | unknown UART command → host and FPGA got out of sync (press KEY0) |
| LEDR7 | host stopped mid-command > 100 ms; bridge recovered by itself |
| LEDR8 | a multiply has completed since reset |

If `host.py` reports wrong C but correct perf counters, rerun `tb/test_mm_core.py` with the
same matrices; if timing fails at N=8, register the multiplier output in `pe.sv` (2-stage PE)
and update `model/golden_model.py::expected_perf`.

## 5. Rules for this repo

- **Pin changes:** edit `tools/gen_quartus.py` → regenerate. Never hand-edit generated `.qsf/.qpf/.sdc`.
- **RTL changes:** every RTL change must keep `cd tb && pytest` green. Add/extend a test for any fix.
- **Never commit build output** (`db/`, `incremental_db/`, `output_files/`, `build.log`) — `.gitignore` covers it.
- **Timing:** a design with negative slack is *not* done, even if it seems to work on the board.
- Pull before you start, push when you stop. Small commits with clear messages.

## 8. Troubleshooting

| Symptom | Fix |
|---|---|
| `jtagconfig`: "No JTAG hardware available" | Re-plug USB; check `/etc/udev/rules.d/51-usbblaster.rules`; `lsusb` should show `09fb:6001` |
| `quartus_pgm` permission error | udev rule not loaded → `sudo udevadm control --reload-rules && sudo udevadm trigger`, re-plug |
| `/dev/ttyUSB0: Permission denied` | Not in dialout yet → log out/in (or `newgrp dialout`) |
| Quartus fails to start: missing `libncurses.so.5` / `libtinfo.so.5` | Ubuntu 24.04: install the 22.04 `.deb`s of `libtinfo5` + `libncurses5` manually |
| Quartus GUI crashes on start | Run the command-line flow (`tools/build.sh`) — the GUI isn't needed |
| Nothing happens on board | Pins wrong (Task 1) or KEY0 held (it's reset) |
| UART garbage / no echo | TX/RX crossed? GND shared? adapter at 3.3 V? correct `.sof` loaded? |
| pytest fails only on Ubuntu | Icarus 11 vs 13 difference → record the exact error in §6 |
